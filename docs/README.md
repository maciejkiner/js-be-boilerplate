# docs/

Dokumentacja projektu traktowana jak kod: aktualizowana w tych samych PR-ach, które zmieniają
konwencje (patrz Definition of Done w `CLAUDE.md`).

- `recipes/` — **przepisy**: „jak dodać encję", „jak dodać providera tożsamości",
  „jak zaktualizować DS" itd. Każdy przepis jest jednocześnie dokumentacją dla człowieka,
  instrukcją dla agenta i specyfikacją scaffoldera. Wypełniane od Fazy 2 wzwyż.
- `adr/` — Architecture Decision Records. Szablon: `../adr-template.md`.
- `ds-component-inventory.md` — inwentarz komponentów design systemu (słownik dla generatorów).
